# 5.0. Database Design

El esquema fisico de base de datos de Ya Quedo esta implementado en PostgreSQL 16 y versionado mediante Flyway en la ruta `tb2/backend/application/src/main/resources/db/migration/`. Esta seccion documenta el diseno relacional resultante de cuatro migraciones (V1-V4) que conforman el modelo de persistencia del sistema.

## Resumen general

| Tabla | Proposito | Filas seed | FKs salientes |
|---|---|---|---|
| `users` | Cuentas de usuario con rol (CLIENTE, TRABAJADOR, ADMIN) y autenticacion | 5 | — |
| `categorias_servicio` | Catalogo maestro de tipos de servicio tecnico | 6 | — |
| `clientes` | Perfil del cliente vinculado a `users` (1:1) | 1 | `usuario_id → users.id` |
| `trabajadores` | Perfil del trabajador con categoria, rating y disponibilidad | 3 | `usuario_id → users.id`, `categoria_id → categorias_servicio.id` |
| `solicitudes_servicio` | Pedidos de servicio con maquina de estados | 2 | `cliente_id → clientes.id`, `trabajador_id → trabajadores.id` |
| `resenas` | Calificacion del cliente al trabajador post-servicio | 1 | `solicitud_id`, `trabajador_id`, `cliente_id` |
| `notificaciones` | Mensajes asincronos para el usuario | 3 | `usuario_id → users.id` |

## Detalle por tabla

### `users`

| Campo | Tipo | Restricciones |
|---|---|---|
| `id` | UUID | PK, default `gen_random_uuid()` |
| `email` | VARCHAR(120) | NOT NULL, UNIQUE |
| `password_hash` | VARCHAR(255) | NOT NULL — BCrypt con strength 12 |
| `role` | VARCHAR(20) | NOT NULL, CHECK `IN ('CLIENTE','TRABAJADOR','ADMIN')` |
| `estado_activo` | BOOLEAN | NOT NULL, default TRUE |
| `email_verificado` | BOOLEAN | NOT NULL, default FALSE |
| `created_at` | TIMESTAMP | NOT NULL, default `CURRENT_TIMESTAMP` |

Indices: `idx_users_email`.

### `categorias_servicio`

| Campo | Tipo | Restricciones |
|---|---|---|
| `id` | UUID | PK |
| `nombre` | VARCHAR(60) | NOT NULL, UNIQUE |
| `descripcion` | VARCHAR(240) | — |

Datos seed: Gasfiteria, Electricidad, Pintura, Carpinteria, Tecnico TV, Cerrajeria.

### `clientes`

| Campo | Tipo | Restricciones |
|---|---|---|
| `id` | UUID | PK |
| `usuario_id` | UUID | NOT NULL, UNIQUE, FK `users(id)` ON DELETE CASCADE |
| `nombres` | VARCHAR(80) | NOT NULL |
| `apellidos` | VARCHAR(80) | NOT NULL |
| `telefono` | VARCHAR(9) | — |

Indices: `idx_clientes_usuario`.

### `trabajadores`

| Campo | Tipo | Restricciones |
|---|---|---|
| `id` | UUID | PK |
| `usuario_id` | UUID | NOT NULL, UNIQUE, FK `users(id)` ON DELETE CASCADE |
| `categoria_id` | UUID | NOT NULL, FK `categorias_servicio(id)` |
| `ubicacion_id` | UUID | — (preparado para georeferenciacion) |
| `nombres` | VARCHAR(80) | NOT NULL |
| `apellidos` | VARCHAR(80) | NOT NULL |
| `telefono` | VARCHAR(9) | — |
| `dni` | VARCHAR(8) | — |
| `calificacion_promedio` | DOUBLE PRECISION | NOT NULL, default 0.0 |
| `disponibilidad` | BOOLEAN | NOT NULL, default TRUE |

Indices: `idx_trabajadores_categoria`, `idx_trabajadores_rating` (DESC, para listados por reputacion).

### `solicitudes_servicio`

| Campo | Tipo | Restricciones |
|---|---|---|
| `id` | UUID | PK |
| `cliente_id` | UUID | NOT NULL, FK `clientes(id)` |
| `trabajador_id` | UUID | NOT NULL, FK `trabajadores(id)` |
| `ubicacion_id` | UUID | — |
| `estado` | VARCHAR(20) | NOT NULL, default 'PENDIENTE', CHECK `IN ('PENDIENTE','ACEPTADA','RECHAZADA','EN_PROGRESO','FINALIZADA','CANCELADA')` |
| `fecha_programada` | TIMESTAMP | — |
| `descripcion` | VARCHAR(500) | — |
| `precio_acordado` | DOUBLE PRECISION | — |
| `created_at` | TIMESTAMP | NOT NULL, default `CURRENT_TIMESTAMP` |

**Maquina de estados** implementada en `SolicitudService`:

```
PENDIENTE ──aceptar──> ACEPTADA ──iniciar──> EN_PROGRESO ──finalizar──> FINALIZADA
   │                       │                                                │
   ├─rechazar──> RECHAZADA  └─cancelar──> CANCELADA                          │
   └─cancelar──> CANCELADA                                                   │
                                                                             v
                                                                  (habilita resena)
```

Indices: `idx_solicitudes_cliente`, `idx_solicitudes_trabajador`, `idx_solicitudes_estado`.

### `resenas`

| Campo | Tipo | Restricciones |
|---|---|---|
| `id` | UUID | PK |
| `solicitud_id` | UUID | NOT NULL, UNIQUE, FK `solicitudes_servicio(id)` |
| `trabajador_id` | UUID | NOT NULL, FK `trabajadores(id)` |
| `cliente_id` | UUID | NOT NULL, FK `clientes(id)` |
| `puntuacion` | INT | NOT NULL, CHECK BETWEEN 1 AND 5 |
| `comentario` | VARCHAR(500) | — |
| `fecha` | TIMESTAMP | NOT NULL, default `CURRENT_TIMESTAMP` |

UNIQUE en `solicitud_id` garantiza una sola resena por solicitud. El servicio recalcula `trabajadores.calificacion_promedio` al insertar.

### `notificaciones`

| Campo | Tipo | Restricciones |
|---|---|---|
| `id` | UUID | PK |
| `usuario_id` | UUID | NOT NULL, FK `users(id)` ON DELETE CASCADE |
| `mensaje` | VARCHAR(500) | NOT NULL |
| `tipo` | VARCHAR(30) | NOT NULL |
| `leida` | BOOLEAN | NOT NULL, default FALSE |
| `created_at` | TIMESTAMP | NOT NULL, default `CURRENT_TIMESTAMP` |

Indice compuesto: `idx_notificaciones_usuario (usuario_id, created_at DESC)` para listado eficiente del feed.

## Decisiones de diseno

| Decision | Justificacion |
|---|---|
| UUID como PK en todas las tablas | Evita exposicion de cantidad de registros, generacion distribuida sin coordinacion, mejor portabilidad para integraciones externas |
| `password_hash` con BCrypt strength 12 | Resistente a ataques de diccionario (2^12 iteraciones), recomendado por OWASP 2024 |
| Maquina de estados via CHECK en `estado` | Refuerzo del invariante a nivel de BD (no solo aplicacion) |
| `categorias_servicio` como tabla maestra (no enum) | Permite agregar categorias sin redeploy, soporta i18n a futuro |
| Indices DESC en `calificacion_promedio` | Listados por reputacion son la query mas frecuente |
| `ON DELETE CASCADE` en clientes/trabajadores | Borrado de usuario limpia perfiles asociados (cumple GDPR) |
| Flyway versionado | Reproducibilidad del schema en local + Railway sin scripts manuales |

## Migraciones aplicadas

| Version | Archivo | Proposito |
|---|---|---|
| V1 | `V1__init_schema.sql` | Crea las 7 tablas + indices + extension pgcrypto |
| V2 | `V2__seed_catalog.sql` | Inserta 6 categorias de servicio |
| V3 | `V3__seed_demo_users.sql` | Inserta 5 usuarios demo + perfiles cliente/trabajador + 2 solicitudes + 1 resena + 3 notificaciones |
| V4 | `V4__fix_seed_password_hashes.sql` | Corrige hashes BCrypt para que `password123` funcione en login |

Las migraciones se aplican automaticamente al arrancar Spring Boot (Flyway autoconfigured), tanto en local Docker como en Railway prod.
