# 5.1.1. Software Configuration Management

Esta seccion presenta las herramientas y practicas utilizadas para asegurar una correcta gestion del desarrollo del producto Ya Quedo durante todo el ciclo de vida del software.

| Categoria | Herramienta | Proposito en el proyecto |
|---|---|---|
| Project Management | **Trello** | Tablero Scrum con columnas To-do / In-Process / To-Review / Done para los 3 sprints. Permite a Jose y Yago repartir tareas, estimar story points y trackear avance |
| Project Management | **WhatsApp** | Comunicacion async del equipo (decisiones rapidas, screenshots, links). Usado tambien para coordinar el reparto del deploy publico de TB3 |
| Project Management | **Google Meet** | Sprint Planning y Sprint Review sesiones semanales con video y screen sharing |
| Requirements Management | **Markdown + GitHub Issues** | Cada User Story se documenta como issue del repositorio con criterios de aceptacion, etiquetas (`sprint-3`, `module:auth`) y se cierran al merge del PR correspondiente |
| Requirements Management | **Notion** | Documento maestro de los Problem Statements + Lean UX assumptions + canvas Lean Startup |
| Product Design | **Figma** | Wireframes Lo-Fi + Hi-Fi del Landing Page y del Web App (44 pantallas: 22 desktop + 22 mobile) |
| Product Design | **Lucidchart / Structurizr** | Diagramas C4 (Context, Container, Components) y diagramas de clase OO |
| Software Development | **IntelliJ IDEA Community** | IDE para backend Spring Boot con soporte nativo de Lombok, MapStruct y Maven |
| Software Development | **Visual Studio Code** | IDE para frontend Angular con extensiones Angular Language Service y ESLint |
| Software Development | **Docker Desktop** | Containerizacion del stack local (Postgres + pgAdmin + Backend + Frontend) con `docker compose up` |
| Software Development | **GitHub** | Hosting del codigo + Pull Requests + Releases con tag `v1.0.0` |
| Software Testing | **JUnit 5 + Mockito 5 + AssertJ** | Framework de testing unitario del backend (31 tests cubriendo las 11 US del Sprint Backlog) |
| Software Testing | **Postman** | Coleccion con 34 endpoints + environment local/prod + tests de auto-captura de JWT |
| Software Testing | **pgAdmin** | GUI para verificar el estado de la BD (filas seedeadas, hashes BCrypt, transiciones de estado) |
| Software Testing | **Swagger UI (springdoc)** | Documentacion interactiva del API + ejecucion de requests para QA manual |
| Software Documentation | **README.md** | Stack, prerequisitos, como correr local + Docker, credenciales seed, deploy a Railway/Vercel/Render. Patron alineado a `hampcodes/pagoya-api` y `hampcodes/pagoya-web` |
| Software Documentation | **Markdown en `tb2/informe-tb3/`** | Secciones del Capitulo V del informe (Sprint Planning, Backlog, Development, Testing, Deployment, Collaboration) versionadas en Git |
| Software Documentation | **GitHub Releases** | Notas de version del release v1.0.0 con descripcion completa del Sprint Review TB3 |
| Software Documentation | **Conventional Commits** | Mensajes de commit con prefijos `feat(modulo):`, `fix(modulo):`, `chore:`, `docs:`, `test:` para auto-generar changelog |
